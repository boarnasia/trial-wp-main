# サイトの単体起動を廃止し、MySQL を 1 台に集約してユーザーを共用する

wp-main からサイトの起動・停止ができるようになり、サイトごとに MySQL を持つ構成と「サイトのディレクトリで単体起動」の二本立ては、DB の二重化と分岐の多さに見合わなくなった。そこで wp-main をメインコントローラーとし、コンテナ定義はすべて wp-main が持ち、サイトのリポジトリはサイトの中身とサイト設定だけを持つことにした。MySQL は共有インフラとして 1 台だけ動かし、サイトごとに schema を分け、DB ユーザーは 1 つを共用する。

## Considered Options

- **サイトごとに DB ユーザーを分ける**: 本番に近い分離になるが、ローカル開発では他サイトの schema に触れられても実害がなく、接続情報を 1 か所（wp-main の `.env`）にまとめる簡潔さを取った。
- **単体起動を残し、サイト側にも MySQL を残す**: 起動方法によって DB が別物になり、データが分かれるため不採用。
- **サイト側に compose を残して wp-main が include する**: サイト固有サービスをサイト側に書ける利点はあるが、単独では動かない compose がサイトに残ることになるため、定義は wp-main に寄せた。

## Consequences

- サイトのリポジトリだけを clone しても WordPress は起動できない。必ず wp-main から起動する。
- サイト同士は DB 上で分離されていない。WordPress やプラグインは同じユーザーで他サイトの schema も読み書きできる。
- 共有 MySQL のメジャーバージョンは全サイト共通になる。サイトごとに違う MySQL を使いたくなったら、この決定を見直す。
