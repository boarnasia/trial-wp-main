## Purpose

ダッシュボードから wp1 / wp2 の状態を確認し、ブラウザの操作だけでサイトを起動・停止できるようにする。操作はホストの Docker に対して行うため、意図しない操作を防ぐ安全策もここで定める。

## ADDED Requirements

### Requirement: サイトの状態の表示
ダッシュボードのサイト一覧は、各サイトの行に、そのサイトの WordPress コンテナと DB コンテナの状態を「起動中」「停止中」「一部停止」のいずれかで表示しなければならない (MUST)。状態はページを開くたびに Docker から取得しなければならない (MUST)。Docker に接続できない場合は、エラーページにせず、状態を取得できないことを表示し、起動・停止のボタンを無効にしなければならない (MUST)。

#### Scenario: 起動中のサイト
- **WHEN** `wp1-wordpress` と `wp1-db` が起動している状態でダッシュボードを開く
- **THEN** wp1 の行に「起動中」と停止のボタンが表示される

#### Scenario: 停止中のサイト
- **WHEN** wp2 のコンテナが両方とも停止している（または存在しない）状態でダッシュボードを開く
- **THEN** wp2 の行に「停止中」と起動のボタンが表示される

#### Scenario: Docker に接続できない
- **WHEN** Docker Desktop が停止している状態でダッシュボードを開く
- **THEN** HTTP 200 が返り、各サイトの行に状態を取得できないことが表示され、起動・停止のボタンは無効になる

### Requirement: サイトの起動と停止
ダッシュボードは、起動のボタンでそのサイトの DB と WordPress を起動し、WordPress が起動して DB が healthy になるまで待たなければならない (MUST)。停止のボタンでそのサイトの WordPress と DB を停止しなければならない (MUST)。停止ではコンテナとボリュームを削除してはならない (MUST NOT)。操作は、コンテナが属する Compose プロジェクトで行わなければならない (MUST)。コンテナがない場合、または wp-main のプロジェクトに属する場合は wp-main のプロジェクトで、そのサイトのディレクトリのプロジェクト（単体起動）に属する場合はそのサイトのディレクトリで操作しなければならない (MUST)。他のサイトとプロキシのコンテナに影響を与えてはならない (MUST NOT)。操作が終わったら、結果（成功または失敗の理由）をサイト一覧に表示しなければならない (MUST)。起動は 120 秒以内に終わらなければ失敗として扱わなければならない (MUST)。

#### Scenario: 停止する
- **WHEN** 一括起動した環境で、wp1 の停止のボタンを選ぶ
- **THEN** `wp1-wordpress` と `wp1-db` が停止し、`wp2-*` と `wp-caddy` は起動したままで、wp1 の行が「停止中」になる

#### Scenario: 起動する
- **WHEN** wp1 が停止している状態で、wp1 の起動のボタンを選ぶ
- **THEN** `wp1-db` が healthy になり、`wp1-wordpress` が起動し、wp1 の行が「起動中」になり、`https://local.wp1.yamashita109.com/` が応答する

#### Scenario: 単体起動したサイト
- **WHEN** `{root}/wp-wp2` で単体起動した wp2 を、ダッシュボードから停止する
- **THEN** wp2 のプロジェクトのコンテナが停止し、wp-main のプロジェクトに `wp2-*` のコンテナは作られない

#### Scenario: 失敗する
- **WHEN** wp1 の `.env` がない状態で wp1 の起動のボタンを選ぶ
- **THEN** 起動は行われず、wp1 の行に失敗の理由が表示される

### Requirement: 同時実行の防止
同じサイトに対する起動・停止が実行中の間、そのサイトへの新しい起動・停止の要求は実行せずに、実行中であることを返さなければならない (MUST)。実行中のサイトの行では、ボタンを無効にしなければならない (MUST)。

#### Scenario: 二重に押す
- **WHEN** wp1 の起動が終わる前に、別のタブから wp1 の停止を要求する
- **THEN** 停止は実行されず、wp1 の操作が実行中である旨が表示される

### Requirement: 操作の保護
起動・停止の要求は POST でだけ受け付け、CSRF トークンを検証しなければならない (MUST)。トークンがない、または一致しない要求は 403 を返し、Docker を操作してはならない (MUST NOT)。wp-main の `.env` の `PROXY_BIND_ADDRESS` が `127.0.0.1` 以外（未設定は `127.0.0.1` とみなす）の場合、ダッシュボードは起動・停止のボタンを無効にし、要求を 403 で拒否しなければならない (MUST)。

#### Scenario: 別のサイトからの POST
- **WHEN** 別のオリジンのページから、CSRF トークンなしで wp1 の停止を POST する
- **THEN** 403 が返り、wp1 は停止しない

#### Scenario: GET では操作しない
- **WHEN** 停止の URL に GET でアクセスする
- **THEN** 405 が返り、wp1 は停止しない

#### Scenario: LAN に公開している
- **WHEN** wp-main の `.env` に `PROXY_BIND_ADDRESS=0.0.0.0` がある状態でダッシュボードを開く
- **THEN** 起動・停止のボタンは無効で、LAN に公開しているため無効にしている旨が表示され、POST しても 403 が返る
